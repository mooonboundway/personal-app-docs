# 개인 앱 제안서

앱 이름: 배수의 진
작성·수정 날짜: 2026-11-02

## 1. 문제·사용자·핵심 가치

- 첫 사용자와 사용 순간: 시험기간에 공부하다가 놀고 싶어지는 학생(본인)
- 현재 해결 방법과 불편: 1시간 알람을 맞추고 1시간 논 뒤, 알람이 울리면 공부하러 돌아간다. 배수의 진을 친 느낌이 없어서 공부에 집중이 안 되고 계속 더 놀고 싶다.
- 확인한 사실: 본인 한 명의 경험이다. 알람 방식을 써 봤다. 타이머를 넘겨서 놀다가 계획한 공부 시간이 부족해 밤을 샌 적이 있다. 공부 시간을 정할 때 과목을 잘 모르는 채로 대충 정하고 시작했다.
- 아직 확인할 가설과 질문: 남은 여유 시간을 숫자로 보여 주면 공부로 돌아오는 데 도움이 될까? 다른 학생도 같은 불편을 겪을까? (다른 사람 조사는 하지 않았다. 미확인)
- 앱 사용 후 얻을 핵심 도움: 목표 성취를 위한 최소한의 공부 시간을 먼저 확보하고, 남은 시간에서 최소한의 놀 시간(휴식시간)을 확보할 수 있다.
- 사용자 스토리: 시험기간의 학생인 내가 필요한 공부 시간을 먼저 정하고 남은 시간을 확인해서, 최소한의 놀 시간(휴식시간)을 확보하면서도 목표성취를 위한 최소한의 공부 시간을 확보하고 싶다.

## 2. MVP와 범위

| 기능 | 필수·보류·제외 | 이유 |
| --- | --- | --- |
| 마감 시각·필수 생활 시간·필요한 공부 시간·마감 성적 기준 입력 | 필수 | 남은 놀 시간을 계산하려면 이 값들이 필요하다. 필요한 공부 시간은 계산 규칙의 근거가 없어서 사용자가 직접 입력한다. |
| 남은 놀 시간 표시 | 필수 | 마지노선이 눈에 보이면 위기감이 생겨 집중이 잘 될 것 같다. (내 생각, 효과는 미확인) |
| 놀 시간이 끝났을 때 폰 알림 | 필수 | 타이머를 넘겨서 놀다가 밤을 샌 경험이 있고, 놀 때는 폰으로 다른 앱을 쓰므로 앱 밖에서도 알려야 한다. |
| 놀기/공부 전환과 공부 시간 자동 측정 | 필수 | 공부한 만큼 남은 공부 시간이 줄어야 계산이 맞다. 시간이 부족하면 직접 수정 방식으로 바꾼다. (후퇴안) |
| 저장값 초기화 | 필수 | 저장값을 직접 지울 때까지 유지하므로 지우는 방법이 필요하다. |
| 목표 학점으로 공부 시간 자동 계산 (목표 학점 입력 포함) | 보류 | 계산 규칙의 근거가 아직 없어서 직접 입력으로 먼저 써 본 뒤 검토한다. 목표는 필요한 공부 시간에 이미 반영된다. |
| 공부 기록 | 보류 | 기록이 쌓이면 다음에 시간을 정할 때 기준이 되어 더 정밀하게 조절할 수 있을 것 같다. (내 가정, 미확인) |
| 퀴즈로 이해도 확인 | 보류 | 직접 입력 방식을 골라서 중요도가 내려갔다. 결과가 다음 시간 설정의 기준이 될 수 있을 것 같다. (내 가정, 미확인) |
| 과목별 관리 | 보류 | 벼락치기용이라 시험 하나로 합쳐 쓰는 게 기본이다. 과목별 마감 기준 규칙이 아직 없어서 첫 흐름을 확인한 뒤 검토한다. |
| 학점 하락 애니메이션 | 제외 | 있으면 좋지만 시간이 부족하다. 여유가 생기면 다시 생각해 볼 아이디어로 메모만 남긴다. |
| 로그인·서버 저장·서버 푸시 | 제외 | 로그인 정보를 쓰는 기능이 없고, 로그인 없이 핵심 기능을 쓸 수 있다. 폰 안에서 울리는 알림은 필수 기능이 맡는다. |

참고(미확인): 계획적으로 공부하는 사람은 열품타 같은 앱을 쓸 것 같다는 내 생각이다. 직접 열어 본 것이 아니므로 9주차 유사 앱 조사에서 확인한다.

## 3. 제약과 결정

- 실행 환경과 확인 상태: Windows PC와 Android 에뮬레이터(Pixel_7)에서 개발환경 점검(flutter doctor)은 통과한 상태이다. 앱은 아직 만들지 않았고 실행하지 않았다(미실행). 폰 알림이 실제로 울리는지는 미확인이다.
- 시간·인원·사용할 기술: 혼자(1명), Flutter·Dart. 구현은 10주차부터 시작한다(수업 계획 기준). 시간이 부족하므로 필수 기능 5개에 집중한다.
- 저장 위치와 유지 기간: 폰 안에 저장하고 사용자가 직접 지울 때까지 유지한다(기말 시험기간에도 이어 쓰기 위해). 저장 방식을 Flutter에서 어떻게 만드는지는 미확인이다.
- 외부 서비스와 개인정보: 서버·로그인·외부 서비스를 쓰지 않는다. 폰 알림을 사용한다(알림 권한이 필요한지는 미확인). 시간과 학점 기준만 다루고 이름·연락처는 받지 않는다.
- 중요한 선택의 상황·선택지·결정·영향:
  - 선택 1. 상황: 앱이 필요한 공부 시간을 어떻게 알게 할 것인가. 선택지: 사용자가 직접 입력 / 목표 학점으로 자동 계산. 결정: 직접 입력. 영향: 사용자가 시간을 잘못 잡으면 결과도 어긋난다. 자동 계산은 규칙의 근거가 없어 보류했다.
  - 선택 2. 상황: 공부한 만큼 필요한 공부 시간을 어떻게 줄일 것인가. 선택지: 직접 수정 / 앱이 자동 측정 / 직접 기록. 결정: 공부 시작·놀기 시작 버튼으로 앱이 자동 측정. 영향: 구현이 늘어난다. 후퇴안: 시간이 부족하면 직접 수정 방식으로 바꾼다.
  - 선택 3. 상황: 놀 시간이 없을 때 놀기 시작을 어떻게 할 것인가. 선택지: 버튼을 막는다 / 누를 수 있지만 경고를 띄운다. 결정: 누를 수 있고 크고 강한 경고 문구를 띄운다. 영향: 사용자가 경고를 무시하고 놀 수 있다.
- 개발 규칙 세 가지와 각각의 확인 방법:
  - 규칙 1. 잘못된 입력(지난 마감 시각, 비었거나 0인 공부 시간, 비었거나 음수인 필수 생활 시간, 선택하지 않은 마감 성적 기준)은 한 곳의 같은 규칙으로 막는다. 확인: 해당 값을 넣어 안내가 뜨는지 직접 확인하고, 코드에서 검증하는 곳이 한 곳인지 확인한다.
  - 규칙 2. 코드를 바꿀 때마다 `flutter analyze`를 하고 실제로 실행해 본다. 확인: 분석 결과와 실행 화면을 함께 확인한다.
  - 규칙 3. 필수 기능 5개를 먼저 완성하고 앱 AC 확인을 마친 뒤에만 보류 기능을 추가한다. 제외 기능은 만들지 않는다. 확인: 앱 AC 기록에서 필수 기능 확인이 끝난 뒤의 변경인지 대조하고, 2장 표와 코드의 기능 목록을 맞춰 본다.

## 4. 화면·데이터·상태

- 핵심 흐름: [앱을 처음 연다(저장값 없음)] → [마감 시각·필수 생활 시간·필요한 공부 시간·마감 성적 기준을 입력해 저장하고 "놀기 시작"을 누른다] → [남은 놀 시간이 줄어들고 끝나면 폰 알림이 온다. "공부 시작"을 누르면 공부 시간이 쌓이고 놀 시간이 다시 계산된다]

| 화면·영역 | 사용자 행동 | 바뀌는 값·다음 상태 |
| --- | --- | --- |
| 입력 화면 | 마감 시각, 필수 생활 시간(시간 칸·분 칸), 필요한 공부 시간(시간 칸·분 칸), 마감 성적 기준을 입력하고 저장 | 저장값 생성 후 타이머 화면으로 이동 |
| 입력 화면 | 초기화 버튼 | 저장값 삭제, 입력 화면이 빈 상태로 돌아옴 |
| 타이머 화면 | "놀기 시작" | 모드가 놀기로 바뀜, 남은 놀 시간이 줄어듦, 끝나는 시각에 폰 알림 예약 |
| 타이머 화면 | "공부 시작" | 모드가 공부로 바뀜, 공부 시간이 쌓임, 예약한 알림 취소, 놀 시간 재계산 |

| 데이터 필드 | 자료형 | 예시 | 규칙 |
| --- | --- | --- | --- |
| 마감 시각 | 날짜·시각 | 내일 오전 9시 | 저장 버튼을 누른 순간의 시각보다 뒤여야 한다. 이미 지난 시각이면 스낵바로 안내한다. |
| 필수 생활 시간 | 숫자(분) | 120 (2시간) | 식사·수면 등 꼭 써야 하는 시간의 합이다. 시간 칸과 분 칸으로 입력하고 분 단위로 저장한다. 비었거나 음수이면 스낵바로 안내한다(0은 허용). |
| 필요한 공부 시간 | 숫자(분) | 360 (6시간) | 사용자가 직접 입력한다. 시간 칸과 분 칸으로 입력하고 분 단위로 저장한다. 비어 있거나 0이면 스낵바로 안내한다. |
| 마감 성적 기준 | 선택값(A+~F) | B | 목록에서 고른다. 처음에는 선택하지 않은 상태("선택하세요")이고, 선택하지 않고 저장하면 스낵바로 안내한다. 경고 문구에만 쓰고 계산에는 쓰지 않는다. |
| 현재 모드 | 선택값(대기·놀기·공부) | 놀기 | 저장값이 없으면 대기이다. |
| 모드 시작 시각 | 날짜·시각 | 오늘 오후 8시 | 모드를 바꿀 때 기록한다. |
| 누적 공부 시간 | 숫자(분) | 90 | 공부 모드로 있던 시간만큼 쌓인다. |

빈 상태·잘못된 입력·실패 안내 중 필요한 것:
- 빈 상태: 저장값이 없으면 입력 화면만 보인다.
- 잘못된 입력(문구는 모두 초안):
  - 지난 마감 시각: 스낵바 "이미 지난 시각이에요. 다시 입력해 주세요."
  - 공부 시간이 비었거나 0: 스낵바 "필요한 공부 시간을 입력해 주세요. 0보다 커야 해요."
  - 필수 생활 시간이 비었거나 음수: 스낵바 "필수 생활 시간을 입력해 주세요. 0 이상이어야 해요."
  - 마감 성적 기준을 선택하지 않음: 스낵바 "마감 성적 기준을 선택해 주세요."
- 시간 부족(놀 시간이 0 이하): 안내 "놀 시간이 없어요. 지금은 공부를 시작하세요. 필수 생활 시간을 줄여 다시 입력할 수도 있지만, 수면·식사를 너무 줄이면 건강에 해로울 수 있어요." "놀기 시작"은 누를 수 있고, 누르면 크고 강한 경고 문구(예: "지금이라도 공부해야 B 맞을 수 있어요!", B는 입력한 마감 성적 기준)를 보여 준다. 이 문구는 학점을 계산한 결과가 아니라 경고용 문구이다.
- 알림: 알림 구현 방법과 권한은 미확인이다.

## 5. 앱 인수 조건

| ID | 시작 상태와 행동 | 기대 결과 | 확인 방법·증거 | 실제 상태 |
| --- | --- | --- | --- | --- |
| AC1 | 저장값 없음. 지금보다 뒤의 마감 시각, 필수 생활 2시간, 필요한 공부 6시간을 입력하고 마감 성적 기준 B를 선택해 저장 | 타이머 화면으로 이동하고 놀 수 있는 시간이 마감까지 남은 시간에서 2시간과 6시간을 뺀 값으로 표시됨 | 값을 직접 계산해 화면과 비교 | 미실행 |
| AC2 | 다음 네 경우를 각각 따로 입력하고 저장: 이미 지난 마감 시각 / 필요한 공부 시간을 비우거나 0 / 필수 생활 시간을 비우거나 음수 / 마감 성적 기준을 선택하지 않음 | 경우마다 해당 스낵바 안내가 뜨고 화면은 이동하지 않으며 저장값은 변하지 않음 | 네 경우를 각각 따로 입력해 안내·화면 유지·저장값 불변을 따로 기록 | 미실행 |
| AC3 | 저장값 없이 앱을 처음 연다 | 입력 화면이 보이고 타이머 화면은 없음 | 첫 화면 확인 | 미실행 |
| AC4 | 필수 생활 시간과 필요한 공부 시간의 합이 마감까지 남은 시간보다 크게 입력(마감 성적 기준 B). "놀기 시작"을 누른다 | 놀 시간이 없다는 안내와, B가 들어간 크고 강한 경고 문구가 뜸 | 경고 문구와 안내를 함께 확인 | 미실행 |
| AC5 | 놀기 시작 후 남은 놀 시간이 0이 될 때까지 기다린다(앱은 다른 앱을 쓰는 중) | 앱 밖에서도 폰 알림이 옴 | 알림이 뜨는지 확인. 알림 구현 방법은 미확인 | 미실행 |
| AC6 | 놀기 중 "공부 시작"을 누른다 | 모드가 공부로 바뀌고 예약된 알림이 취소됨. 공부 시간이 쌓이고 놀 시간이 다시 계산됨 | 모드, 알림 취소, 값 변화를 확인 | 미실행 |
| AC7 | 값을 저장한 뒤 앱을 닫았다 켠다. 이어서 초기화 버튼을 누른다 | 닫았다 켜도 값이 남아 있고, 초기화 뒤에는 입력 화면이 빈 상태로 돌아옴 | 두 경우를 차례로 확인 | 미실행 |

계획을 작성한 상태와 앱 실행 결과를 구분합니다. 실제로 실행하기 전에는 통과로 바꾸지 않습니다.
